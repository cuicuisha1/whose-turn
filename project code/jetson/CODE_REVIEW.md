# v0.2 代码复核与 v0.2.1 修订

2026-10-28。复核范围：新机器人主程序、视觉监督、模块契约、行为/执行边界、状态页、记录器、Arduino 状态适配器和打包交付。Arduino 固件仅核对源码哈希与接口语义，未修改或烧录。

## 已修复

| 优先级 | 触发条件与影响 | 修复 |
| --- | --- | --- |
| P1 | SIGINT/SIGTERM 在主线程持有命令队列锁时到达，原信号处理器再次向队列投递命令，可能死锁，导致无法正常退出 | 信号处理器只设置布尔标志；由普通主循环入队。隔离子进程测试在持锁期间实际触发 SIGINT，验证正常退出 |
| P2 | 状态文件写入失败后，finally 再次写同一路径报错，可能跳过日志关闭和信号恢复；JSONL 默认 logging 处理器还可能吞掉写入失败 | 收尾的状态/摘要写入单独捕获错误，保证回收资源与恢复处理器；新增 output_errors，失败退出码为 2；JSONL 写入错误显式传播 |
| P2 | Arduino 监控线程已结束并关闭串口，但其快照仍保留 connected=true；关闭异常也未传回主程序 | 关闭/请求停止后清除连接与当前状态，关闭失败回传 serial_close_failed 并影响退出码 |
| P2 | JSON 的 true/1.0 会与整数版本 1 相等，可能被当作合法 schema；非法命令种类为列表/对象时会抛出非预期 TypeError | 精确检查 schema 的整数类型，命令种类/来源/时间戳显式校验并统一 ValueError |
| P3 | 定时正常退出时 states_seen 和事件日志缺少最终 STOPPED | 所有正常/异常收尾都记录最终停止状态，避免与 latest.json 不一致 |

信号修复遵循 [Python 官方 signal 文档](https://docs.python.org/3/library/signal.html#signals-and-threads)关于信号处理器内锁操作的约束。

## 新增回归验证

1. 持有命令队列锁时触发真实 SIGINT，子进程按时正常退出。
2. 状态写入持续失败，设备仍关闭、信号处理器恢复、摘要报告错误。
3. 摘要写入失败，标准输出仍报告最终错误且退出码为 2。
4. 注入 JSONL 流写入失败，验证错误不被静默忽略。
5. 串口关闭失败，连接状态失效并回报关闭错误。
6. 非法 schema/命令类型及非有限时间戳被拒绝。
7. 视觉子进程输出非 JSON，监督器清空消息、终止并回收进程。

原有测试继续覆盖真正在本机启动的视觉子进程、HTTP API、固件模拟器、感知过期、暂停恢复和停止流程。完整结果写入 `build/robot`；对应交付包使用版本 `0.2.1`，保留首次生成的 v0.2 ZIP 以便追溯。

修订后完整验证结果：**60 项通过、0 失败、0 错误、0 跳过**。

## 尚待验证的边界

Jetson/RealSense 实机环境、长期稳定性和真实串口没有在本次本地复核中得到验证。真实运动、ASR/TTS 和导航仍未实现；现有单开关硬件也没有可由本程序控制的动力切断。代码复核和模拟通过不代表这些硬件能力已经可用。
